# iOS Setup Guide for Antigravity Home Widgets

Setting up iOS widgets requires a few manual steps in Xcode to create the Widget Extension target and configure data sharing.

## 1. Create a Widget Extension Target

1.  Open your project in **Xcode**.
2.  Go to **File > New > Target...**.
3.  Select **Widget Extension** and click **Next**.
4.  Product Name: `HomeWidgetExtension` (Recommended).
5.  Uncheck "Include Configuration Intent" (for now).
6.  Click **Finish**.
7.  If asked to activate the scheme, click **Activate**.

### 🧹 Cleanup Boilerplate
Xcode creates several default files that will conflict with our generated code. **Delete these files from the `HomeWidgetExtension` folder**:
- `HomeWidgetExtension.swift`
- `HomeWidgetExtensionBundle.swift`
- `HomeWidgetExtensionControl.swift`
- `HomeWidgetExtensionLiveActivity.swift`
- `AppIntent.swift` (if present)

Ensure you also check the **Trash** or choose **Move to Trash** in Xcode to avoid duplicate file errors.

## 2. Configure App Groups

Both your main App and the Widget Extension need to be in the same **App Group** to share data.

1.  Select your project in the Sidebar.
2.  For the **Main App Target**:
    -   Go to **Signing & Capabilities**.
    -   Click **+ Capability** and add **App Groups**.
    -   Add a new group (e.g., `group.com.yourname.myapp`).
3.  Repeat these steps for the **Widget Extension Target**.
    -   Ensure it uses the **exact same** App Group ID.
4.  Update your `home_widget.yaml` with the group ID:
    ```yaml
    app:
      ios_app_group: group.com.yourname.myapp
    ```

## 3. Generate and Add Files

1.  Run the build command:
    ```bash
    dart run hw_cli build
    ```
2.  In Xcode, right-click your `HomeWidgetExtension` folder and select **Add Files to "Runner"...**.
3.  Navigate to `ios/HomeWidgetExtension` and select all `.swift` files generated by the CLI.
4.  **IMPORTANT**: In the "Add Files" dialog, ensure **only** the `HomeWidgetExtension` target is selected in the "Add to targets" section.

## 4. Main Widget Entry Point

The CLI now automatically generates a `HomeWidgetBundle.swift` file that includes all your widgets. You don't need to write any Swift entry point code manually! Just ensure this file is added to your target in Section 3.

## 5. Sharing Data from Flutter

The `hw_flutter` bridge handles sharing data via `UserDefaults` using the App Group. No extra native code is needed for standard data binding!

```dart
await HomeWidgetBridge.saveString('news_title', 'Hello iOS!');
await HomeWidgetBridge.refreshAll();
```

## 6. Troubleshooting

### 🔴 Error: "Cycle inside Runner; building could produce unreliable results"

This is a common Xcode issue when adding Extensions to a Flutter project. It happens because the build system tries to embed the widget before the main app processing is done.

**Fix:**
1.  Open `ios/Runner.xcworkspace` in Xcode.
2.  Select the **Runner** project (blue icon) -> **Runner** target.
3.  Go to the **Build Phases** tab.
4.  Find the **"Embed Foundation Extensions"** phase.
5.  **Drag and drop** it to the very bottom of the list, **after** the "Thin Binary" script and "Embed Frameworks".
6.  **Clean Build Folder** (Product > Clean Build Folder) and run again.

### 🔴 Error: "Scanner has no member scanUint64"

This has been fixed in the latest version of `hw_cli`. Run `dart run hw_cli build` to regenerate the Swift code with the correct syntax.

### 🔴 Widgets Not Showing in Simulator

iOS Widgets may not appear in the standard ARM simulator. **Use a Rosetta simulator** instead:
1.  In Xcode, go to **Product > Destination > Destination Architectures > Show Rosetta Destinations**.
2.  Select a device with "(Rosetta)" in its name.
3.  Run the app again and add the widget to the home screen.
